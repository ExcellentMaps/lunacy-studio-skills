# Открытые инструменты проверки

---

Бесплатные инструменты, которыми проверяют проект. Ни один из них не заменяет чтение
кода: самые опасные дыры в CRM — это логика прав, и её видит только человек.

---

## ⚠️ Предупреждение об активных сканерах

`nuclei` и `OWASP ZAP` — **активные** сканеры. Они не просто смотрят ответы, а сами
шлют проверочные запросы: перебирают адреса, отправляют формы, подставляют значения.

Три правила, без исключений:

1. **Только по своему проекту.** Запуск активного сканера по чужому сайту — это атака,
   независимо от намерений, и последствия у неё соответствующие.
2. **Только с разрешения владельца**, полученного заранее и явно. Устного «да, проверь»
   достаточно, молчаливого согласия — нет.
3. **Желательно не по боевому серверу.** Активный скан даёт нагрузку, забивает журнал,
   создаёт мусорные записи в базе и может разослать письма через формы. Правильно —
   по тестовой копии, а если по боевому, то в тихое время и предупредив владельца.

Остальные инструменты читают код, файлы и ответы сервера и в этом смысле безопасны,
но правило «только свой проект» действует и для них.

## gitleaks — секреты в коде и в истории git · github.com/gitleaks/gitleaks

**Когда звать:** при первом аудите любого проекта, обязательно. И перед тем, как
открыть репозиторий наружу или передать его подрядчику.

```bash
brew install gitleaks   # или бинарник со страницы релизов
gitleaks detect --source . --redact --report-path gitleaks.json   # --redact прячет значения
```

**Не находит:** секреты, не похожие на секреты по виду, — пароль, записанный обычным
словом. И не говорит, действует ли найденный ключ: это проверяется руками.

## osv-scanner — уязвимые зависимости · github.com/google/osv-scanner

**Когда звать:** при аудите и регулярно потом. Уязвимости появляются в библиотеках,
которые вы не меняли.

```bash
go install github.com/google/osv-scanner/cmd/osv-scanner@latest
osv-scanner -r .        # в новых версиях: osv-scanner scan source -r .
```

**Не находит:** то, о чём ещё не сообщили, и ошибки в вашем коде. Ещё частое: уязвимая
функция в библиотеке есть, но вы её не вызываете — сканер этого не различает.

## semgrep — разбор исходного кода · github.com/semgrep/semgrep

**Когда звать:** при аудите кода и в проверках перед выпуском изменений.

```bash
pip install semgrep
semgrep --config auto .
```

**Не находит:** ошибки в правах и бизнес-логике. Код, где сотруднику разрешено смотреть
чужие карточки, для сканера выглядит нормально.

---

## trivy — контейнеры и файлы настройки · github.com/aquasecurity/trivy

**Когда звать:** если проект собирается в контейнер или разворачивается по описанию
инфраструктуры.

```bash
brew install trivy      # или пакет для вашей системы
trivy image ИМЯ_ОБРАЗА:ТЕГ
trivy fs . && trivy config .
```

**Не находит:** логику прав. И не видит, как контейнер настроен в реальном окружении:
переменные и права запуска задаются снаружи.

## nuclei — ⚠️ шаблонные проверки веба · github.com/projectdiscovery/nuclei

**Когда звать:** после проверки кода, только по своему проекту и с разрешения владельца.
Перечитать блок предупреждения выше.

```bash
go install github.com/projectdiscovery/nuclei/v3/cmd/nuclei@latest
nuclei -u https://ВАШ_ДОМЕН
```

**Не находит:** всё, что за входом в систему. Шаблоны проверяют публичную часть,
а основная ценность CRM лежит внутри, под паролем.

---

## lynis — настройки Linux-сервера · github.com/CISOfy/lynis

**Когда звать:** когда сервер свой и настраивали его вы или подрядчик.

```bash
git clone https://github.com/CISOfy/lynis && cd lynis
sudo ./lynis audit system
```

**Не находит:** ничего про ваше приложение и базу, это проверка операционной системы.
Замечаний выдаёт много, и не все из них надо закрывать.

## testssl.sh — проверка защищённого соединения · github.com/testssl/testssl.sh

**Когда звать:** один раз при аудите и после смены сертификата или хостинга.

```bash
git clone https://github.com/testssl/testssl.sh && cd testssl.sh
./testssl.sh ВАШ_ДОМЕН
```

**Не находит:** ничего, кроме соединения. Хорошая оценка говорит лишь о том, что канал настроен правильно.

## OWASP ZAP — ⚠️ проверка работающего сайта · github.com/zaproxy/zaproxy

**Когда звать:** когда нужно проверить не код, а живое поведение сайта. Те же три
правила, что и для `nuclei`: свой проект, разрешение, лучше не боевой сервер.

```bash
docker run --rm -t zaproxy/zap-stable zap-baseline.py -t https://ВАШ_ДОМЕН
```

Режим `zap-baseline.py` — самый спокойный. Полный активный режим — только по тестовой копии.

**Не находит:** ошибки в правах. ZAP видит сайт глазами одного пользователя и не знает,
что этому пользователю видеть не полагалось.

## Встроенные проверки пакетов

Умеют одно: сверить подключённые библиотеки с базой известных уязвимостей.

| Язык | Команда |
|---|---|
| Node.js | `npm audit --omit=dev` |
| Python | `pip install pip-audit && pip-audit` |
| Go | `go install golang.org/x/vuln/cmd/govulncheck@latest && govulncheck ./...` |
| PHP | `composer audit` |

**Не находят:** ничего, кроме устаревших пакетов. `npm audit` к тому же показывает
уязвимости в инструментах сборки, которые в рабочую систему не попадают, — это шум.

Адреса: github.com/pypa/pip-audit, github.com/golang/vuln, github.com/composer/composer

## Supabase Security Advisor

**Когда звать:** если проект на Supabase — сразу, это первое, что стоит открыть.
Находится в панели проекта, в разделе с советами по безопасности.

**Что показывает:** таблицы без включённой защиты строк, открытые представления,
функции с повышенными правами, слабые настройки входа.

**Не находит:** правильность самих правил доступа. Advisor видит, что защита включена,
но не проверяет, верно ли она написана. Правило, открывающее всю таблицу всем, он
считает нормальной включённой защитой.

**Найти:** панель Supabase, проект → Advisors. Код — github.com/supabase/supabase

## Чего не найдёт ни один сканер

Это проверяется головой, вручную, и именно здесь находятся самые дорогие дыры.

| Что проверять | Почему сканер бессилен |
|---|---|
| Логику прав ролей | Для сканера разрешение выглядит как разрешение, а не как ошибка |
| Доступ к чужим записям | Сканер не знает, какая запись чья и кто имел право её открыть |
| Кому доступен экспорт базы | Выгрузка — это штатная функция, а не уязвимость |
| Проверялось ли восстановление бэкапа | Наличие файла копии не значит, что из неё можно развернуться |
| Что происходит при увольнении | Закрытие доступа и обрыв сессий проверяются только вручную |
| Кто и что видит в журнале | Сканер не читает журнал и не знает, чего в нём не хватает |

Правило простое: **сканеры закрывают механическую часть аудита, а решения принимает
человек.** Чистый отчёт всех инструментов из этого файла не означает, что система
защищена, — он означает только, что известного и механического в ней не нашлось.
