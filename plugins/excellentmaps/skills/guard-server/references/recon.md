Чинить по ходу осмотра — плохая идея: половину находок вы забудете.

## 1. Что слушает сервер и на каком адресе

```bash
ss -tulpn | grep LISTEN
```

Флаги: `t` — TCP, `u` — UDP, `l` — только слушающие, `p` — какая программа,
`n` — номера портов вместо имён. Если `ss` не установлен — `netstat -tulpn`.

Главное в выводе — не номер порта, а **адрес слева от двоеточия**:

| Что видно | Что это значит |
|---|---|
| `127.0.0.1:5432` | Слушает только сам сервер. Из интернета не подключиться. Правильно |
| `[::1]:5432` | То же самое по IPv6 — только сам сервер |
| `0.0.0.0:5432` | Слушает на всех адресах, то есть наружу 🔴 |
| `:::5432` или `[::]:5432` | То же самое через IPv6. Легко пропустить глазами |
| `192.168.1.10:5432` | Конкретный интерфейс — смотреть, внешний он или внутренний |

Типичная ошибка при чтении: увидели `0.0.0.0:443` и испугались. Веб-серверу так и
положено — 80 и 443 должны смотреть наружу. Тревожно, когда наружу смотрит база,
кеш, брокер очередей или панель. Сразу только то, что открыто во внешний мир:

```bash
ss -tulpn | grep LISTEN | grep -vE '127\.0\.0\.1|\[::1\]'
```

## 2. Проверка снаружи — единственная честная

Изнутри сервера всё всегда выглядит доступным. Достоверный ответ на вопрос «что видно
из интернета» даёт только **другая машина** — ноутбук, другой сервер, что угодно вне
проверяемого хоста.

```bash
nc -zv ваш-домен.ru 5432
nc -zv ваш-домен.ru 6379
```

`succeeded` или `open` — порт отвечает из интернета. `Connection refused` или
`timed out` — не отвечает, это то, что нужно.

Если установлен nmap — одним заходом по частым служебным портам:

```bash
nmap -Pn -p 22,80,443,3000,3306,5432,5672,6379,8000,8080,9090,9200,15672,27017 ваш-домен.ru
```

⚠️ Сканировать можно **только свои** серверы. Сканирование чужих хостов во многих
странах — самостоятельное правонарушение, независимо от намерений.

## 3. Состояние firewall

```bash
sudo ufw status verbose
sudo iptables -L -n -v | head -40     # уровень, на котором живут правила Docker
```

`Status: inactive` — firewall выключен, ни одно правило не действует.
`Status: active` — список правил ниже и есть действующая политика.

## ⚠️ Docker обходит ufw

Ловушка, на которую попадаются чаще всего остального.

Запуск вида `-p 5432:5432` (или такая же строка `ports:` в `docker-compose.yml`)
открывает порт **в интернет**, даже если `ufw status` показывает, что всё закрыто.
Причина техническая: Docker пишет правила напрямую в iptables, в цепочку, которая
обрабатывается **раньше** цепочек ufw. Ufw при этом честно показывает свои правила —
просто до них дело не доходит.

| Запись проброса | Кто может подключиться |
|---|---|
| `-p 5432:5432` (то же — `0.0.0.0:5432:5432`) | весь интернет |
| `-p 127.0.0.1:5432:5432` | только сам сервер |
| без `ports:`, только `expose` | только контейнеры той же сети |

Найти все пробросы разом:

```bash
docker ps --format '{{.Names}}\t{{.Ports}}'
grep -n -A4 'ports:' docker-compose.yml
```

В выводе `docker ps` строка `0.0.0.0:5432->5432/tcp` — порт наружу,
`127.0.0.1:5432->5432/tcp` — порт закрыт.

**Вывод:** `ufw status` не является доказательством закрытого порта. Доказательство —
проверка с другой машины из пункта 2.

## 4. Сертификат: есть ли и когда истекает

```bash
echo | openssl s_client -servername ваш-домен.ru -connect ваш-домен.ru:443 2>/dev/null \
  | openssl x509 -noout -subject -issuer -dates
```

Важны две строки: `notBefore` — с какого момента действует, `notAfter` — до какого.
Сертификаты Let's Encrypt живут 90 дней, и это нормально — их продлевает автоматика.
Тревожный признак не короткий срок, а срок, который не обновляется: осталось меньше
20 дней — автопродление, скорее всего, не работает.

## 5. Заголовки, которые отдаёт сайт

```bash
curl -sSI https://ваш-домен.ru/ \
  | grep -iE 'strict-transport|content-security|x-content-type|referrer|permissions|x-frame|server|x-powered'
```

Проверить, что http перенаправляется на https, а не отвечает копией сайта:

```bash
curl -sSI http://ваш-домен.ru/ | head -5
```

Ожидаемо — `301` и `Location: https://…`.

## 6. Права на файлы с секретами

```bash
ls -la .env* 2>/dev/null
stat -c '%a %U:%G %n' .env 2>/dev/null
sudo find /etc /opt /srv /var/www -maxdepth 4 \( -name '.env' -o -name '*.pem' -o -name '*.key' \) 2>/dev/null
```

Нужное состояние — `600` и владелец того пользователя, от которого работает сервис.
`644` означает, что файл читает любой пользователь системы; `666` и `777` —
однозначная находка.

Отдельно — не отдаётся ли `.env` по прямой ссылке:

```bash
for p in .env .git/config; do curl -sS -o /dev/null -w "$p %{http_code}\n" https://ваш-домен.ru/$p; done
```

`404` или `403` — нормально. `200` — 🔴 красный уровень, дальше `secrets.md`.

## 7. Разрешён ли вход по SSH с паролем

```bash
sudo sshd -T | grep -iE 'passwordauthentication|permitrootlogin|pubkeyauthentication|^port'
```

`sshd -T` показывает **действующую** конфигурацию с учётом всех файлов из
`sshd_config.d/`. Читать сам `sshd_config` глазами менее надёжно: строка ниже по файлу
или в подключённом фрагменте может переопределить то, что вы видите.

| Строка в ответе | Что означает |
|---|---|
| `passwordauthentication yes` | Вход по паролю разрешён — пароль подбирают круглосуточно 🟠 |
| `permitrootlogin yes` | Root может войти по паролю 🔴 |
| `permitrootlogin prohibit-password` | Root только по ключу — приемлемо |
| `pubkeyauthentication yes` | Вход по ключу работает |

Сколько попыток подбора уже было:

```bash
sudo grep -c 'Failed password' /var/log/auth.log 2>/dev/null; sudo lastb | head -20
```

## 8. Версия системы и необновлённые пакеты

```bash
head -3 /etc/os-release; uname -r
apt list --upgradable 2>/dev/null | head -30
apt list --upgradable 2>/dev/null | grep -ci security
```

Если в `/etc/os-release` выпуск, снятый с поддержки, обновления безопасности для него
просто не выходят. Это отдельная находка, и чинится она не патчами, а переездом на
поддерживаемый выпуск.

## 9. Что запускается по расписанию

```bash
crontab -l 2>/dev/null; sudo crontab -l 2>/dev/null
ls -la /etc/cron.d/ /etc/cron.daily/
sudo systemctl list-timers --all | head -20
```

Смотреть на две вещи: нет ли в строках cron паролей и ключей открытым текстом (их видит
каждый, кто читает файл) и нет ли задач, которых вы не ставили.
