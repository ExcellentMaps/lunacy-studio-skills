# Загрузка файлов, iframe и внешние виджеты

Guard Security Suite © ExcellentMaps — github.com/ExcellentMaps

Три способа впустить чужое на свой сайт: файл, который загрузил пользователь; окно
с чужой страницей внутри вашей; скрипт чужой компании, выполняющийся рядом с вашим.
Все три нужны в работе, все три требуют условий.

---

## Часть 1. Загрузка файлов

В CRM грузят договоры, сканы паспортов, результаты анализов, скриншоты переводов,
логотипы клиентов. Файл приходит извне, а значит, к нему применимо то же правило,
что к любому вводу: считать недоверенным, пока не проверено.

### Проверка типа — на сервере и по содержимому

Расширение в имени файла — это просто буквы после точки. Их пишет тот, кто загружает.
Заголовок `Content-Type`, который присылает браузер, — тоже данные от клиента,
и их подделывают одной строкой.

| Проверка | Надёжность |
|---|---|
| Расширение в имени | 🔴 Никакая. Переименовывается за секунду |
| `Content-Type` из запроса | 🔴 Никакая. Присылает клиент |
| Проверка в браузере (`accept`, скрипт формы) | 🟡 Удобство для человека. Запрос отправляют и мимо формы |
| Чтение первых байт файла на сервере (сигнатура формата) | 🟠 Рабочая база |
| Разбор файла подходящей библиотекой на сервере | Надёжнее всего: если библиотека не разобрала — это не тот формат |

Принцип тот же, что везде: **белый список**. Перечисляем разрешённые форматы
(`pdf`, `jpeg`, `png`, `docx`, `xlsx`), а не пытаемся перечислить запрещённые.

⚠️ Атрибут `accept="image/*"` в форме и проверка в JavaScript — это подсказка
для человека, а не защита. Настоящая проверка — на сервере, всегда.

### Лимит размера

Ставится **до** записи файла на диск, на уровне сервера (`client_max_body_size 10m;`
в nginx). Без лимита один человек с толстым каналом забивает диск за вечер — и система
останавливается вся, включая запись в базу. Отдельно нужен лимит на количество файлов
в одной карточке и на общий объём в аккаунте.

### Обеззараживание имени

Имя файла, пришедшее от пользователя, **не используется как имя на диске**. В нём
бывают: `../` для выхода из папки, управляющие символы, имена, зарезервированные
операционной системой, буквы других алфавитов, неотличимые на вид.

Правильный подход: на диске файл получает сгенерированное имя (случайная строка
или идентификатор записи), а исходное имя хранится в базе как обычное текстовое поле
и показывается человеку — через экранирование, как любой другой текст.

### ⚠️ Загруженный HTML и SVG не должен выполняться на домене сайта

Самая недооценённая строка во всём разделе.

Файл, открытый по адресу вашего домена, выполняется **как часть вашего сайта**.
Загруженный HTML-файл или SVG-картинка со скриптом внутри, открытые по ссылке
`https://ваш-домен/files/договор.html`, получают доступ ко всему, что есть у сотрудника
в браузере: куки без `HttpOnly`, содержимое `localStorage`, возможность отправлять
запросы к вашему API от его имени.

Обратите внимание: никакого взлома здесь нет. Система работает штатно — просто
кто-то загрузил в карточку клиента файл и прислал коллеге ссылку на него.

Три способа закрыть:

| Способ | Как |
|---|---|
| **Отдельный домен для файлов** | Лучший вариант. Код на `files-example.ru` не имеет доступа к данным `crm-example.ru`. Именно другой домен, а не поддомен |
| **`Content-Disposition: attachment`** | Браузер не открывает файл, а скачивает. Годится, когда просмотр в браузере не нужен |
| **`Content-Type` строго по факту + `X-Content-Type-Options: nosniff`** | Мешает браузеру «догадаться», что текстовый файл на самом деле HTML |

Хорошая практика — сочетать первое и второе.

### Запрет листинга папки

Открытый адрес папки не должен показывать список лежащих в ней файлов. Иначе одна
ссылка выдаёт все договоры всех клиентов.

```nginx
autoindex off;     # в nginx это умолчание, но проверить стоит
```

Проверка: открыть `https://домен/uploads/` без имени файла. Должен быть отказ,
а не перечень.

### Доступ к файлу — только с проверкой прав

Файлы часто отдаёт веб-сервер напрямую, минуя приложение. Тогда прав никто
не проверяет: у кого есть ссылка, у того есть файл. А ссылки попадают в переписку,
в историю браузера, в заголовок `Referer` при переходе на внешний сайт.

Правильно: запрос на файл проходит через приложение, которое отвечает на два вопроса —
«кто спрашивает» и «имеет ли он отношение к этой записи». Варианты реализации:
отдача файла приложением, внутреннее перенаправление на веб-сервер
(`X-Accel-Redirect` в nginx), либо ссылка с ограниченным сроком жизни.

Проверка: скопировать ссылку на файл и открыть её в окне без авторизации. Должен быть
отказ. Это же — `guard-audit`, блок 9.6.

## Часть 2. iframe и внешние виджеты

### Ваша страница внутри чужого сайта

Обратное направление, про которое забывают: кто-то встраивает **вашу** CRM в свой
сайт, накрывает прозрачным слоем и ловит клики сотрудника.

```
Content-Security-Policy: frame-ancestors 'none';
```

Для закрытой системы — `'none'`. Если встраивание нужно, перечисляются конкретные
разрешённые домены. Это `guard-server`.

### Чужая страница внутри вашей

Атрибут `sandbox` снимает с встроенной страницы почти все права, а затем вы
возвращаете только нужные.

```html
<iframe
  src="https://widget-example.ru/чат"
  sandbox="allow-scripts allow-forms"
  allow="camera 'none'; microphone 'none'; geolocation 'none'"
  referrerpolicy="no-referrer"
  loading="lazy"></iframe>
```

| Разрешение | Что даёт | Замечание |
|---|---|---|
| `allow-scripts` | выполнять JavaScript | обычно нужно |
| `allow-forms` | отправлять формы | по необходимости |
| `allow-same-origin` | 🔴 считать содержимое «своим» | вместе с `allow-scripts` практически отменяет песочницу |
| `allow-popups` | открывать новые окна | по необходимости |
| `allow-top-navigation` | 🟠 уводить всю вкладку на другой адрес | давать не стоит |

Атрибут `allow` управляет доступом к камере, микрофону, геопозиции и прочим
возможностям устройства. Разумно закрывать всё, что виджету не нужно.

**Что видит встроенная страница в любом случае:** факт показа, свои куки, адрес
вашей страницы (если не ограничить `referrerpolicy`), размер окна. Прочитать
содержимое вашей страницы она не может — при условии, что вы не дали
`allow-same-origin` вместе со `allow-scripts`.

Для загруженного пользователем содержимого, которое надо показать как есть: отдельный
домен + `sandbox` без `allow-same-origin`. См. `xss-и-вывод.md`, раздел про случаи,
когда очистка невозможна.

### Внешние скрипты: метрики, чаты, виджеты

```html
<script src="https://аналитика-example.ru/counter.js"></script>
```

Такой скрипт **не в песочнице**. Он выполняется как ваш собственный код и умеет всё
то же самое: читать содержимое страницы, видеть введённое в поля, отправлять запросы
от имени сотрудника, менять разметку.

Житейски: это сотрудник чужой компании, которому вы дали ключ от кабинета и разрешили
приходить когда угодно. Его добросовестность вы не проверяете — просто доверяете.
И доверяете не только компании, но и всем, кто получит доступ к её серверам.

Что учитывать:

- 🔴 В CRM внешних скриптов быть не должно. На странице с карточками клиентов чужому
  коду делать нечего — а данные, которые он увидит, персональные.
- 🟠 На публичном сайте — только необходимое, с пересмотром раз в год: кто это
  поставил и работает ли оно вообще.
- Менеджеры тегов особенно непрозрачны: код меняется в чужой панели, без вашего
  участия и без следа в репозитории.
- Каждый внешний домен попадает в CSP. Если строка в политике есть, а виджета
  давно нет — строка убирается.

### Subresource Integrity

Если внешний скрипт всё же нужен, можно зафиксировать его содержимое: в атрибуте
указывается контрольная сумма, и браузер откажется выполнять файл, если тот изменился.

```html
<script
  src="https://cdn-example.ru/lib-1.2.3.min.js"
  integrity="sha384-ЗДЕСЬ_КОНТРОЛЬНАЯ_СУММА"
  crossorigin="anonymous"></script>
```

Сумма считается так:

```bash
curl -s https://cdn-example.ru/lib-1.2.3.min.js \
  | openssl dgst -sha384 -binary | openssl base64 -A
```

Ограничения, о которых стоит знать:

- работает только с файлами фиксированной версии. Счётчики и чаты обновляют свой
  код постоянно — для них это неприменимо;
- при изменении файла скрипт просто не выполнится. Для библиотеки это лучше, чем
  выполнить подменённый код, но функция перестанет работать — нужен запасной путь;
- 🟡 надёжнее всего вообще не брать библиотеку с чужого сервера, а положить её рядом
  со своей сборкой: внешней зависимости во время работы не остаётся.

## Что проверить

| Проверка | Как |
|---|---|
| Тип файла проверяется на сервере по содержимому | код обработчика загрузки |
| Есть лимит размера на уровне сервера | конфигурация nginx |
| Имя на диске генерируется, исходное хранится отдельно | код |
| Загруженный HTML/SVG не выполняется на домене сайта | загрузить безобидный тестовый файл и открыть его |
| Адрес папки не показывает список файлов | открыть `/uploads/` |
| Файл не открывается по ссылке без входа | открыть ссылку в окне без авторизации |
| Сайт нельзя встроить в чужую страницу | заголовок `frame-ancestors` |
| Список внешних скриптов известен и обоснован | DevTools → Network, колонка Domain |
