# Терминал и генерация ключей — пошагово, для тех, кто это делает впервые

Guard Security Suite © ExcellentMaps — github.com/ExcellentMaps

---

Этот файл — для случая, когда человеку нужно что-то выполнить своими руками, а он
никогда не открывал терминал. Не отправляй его читать документацию. Проведи по шагам.

**Правило:** давай **одну команду за раз**, говори, что человек увидит после неё,
и жди подтверждения. Не сбрасывай список из десяти команд.

---

## Шаг 1. Открыть терминал

Спроси, какая у человека система, и дай только её инструкцию.

### Windows

Рекомендуемый вариант — **PowerShell**:

1. Нажать `Win + X`.
2. Выбрать **«Терминал»** или **«Windows PowerShell»**.
3. Откроется чёрное или синее окно с мигающим курсором. Это он.

Если в проекте есть Git, есть и второй вариант — **Git Bash** (в нём работают
команды из Linux-инструкций):

1. Нажать `Пуск`, набрать `Git Bash`, нажать Enter.

⚠️ Команды для PowerShell и для Git Bash — **разные**. Всегда уточняй, что именно
открыто, прежде чем диктовать команду.

### macOS

1. Нажать `Cmd + Пробел`.
2. Набрать `Терминал` или `Terminal`, нажать Enter.

### Linux

`Ctrl + Alt + T` — в большинстве систем.

### Что сказать человеку сразу после

> Команды копируются целиком и вставляются в окно. В Windows вставка — правая кнопка
> мыши или `Ctrl + V`. Затем Enter. Если после Enter ничего не произошло и появилась
> новая строка — команда выполнилась молча, это нормально.

## Шаг 2. Убедиться, что нужный инструмент есть

Почти всё ниже делается через `openssl`. Проверка:

```bash
openssl version
```

| Что вывелось | Что это значит |
|---|---|
| `OpenSSL 3.x.x ...` | Всё на месте, можно работать |
| `command not found` / «не является внутренней командой» | Инструмента нет — см. ниже |

**Если openssl нет:**

- **Windows:** он есть внутри Git Bash. Откройте Git Bash и повторите проверку там.
  Либо используйте команды PowerShell из таблиц ниже — они не требуют openssl.
- **macOS:** обычно есть. Если нет — `brew install openssl`.
- **Linux (Ubuntu/Debian):** `sudo apt install openssl`.

## Шаг 3. Сгенерировать ключ или пароль

### ⚠️ Сначала — важное про md5

Если человек говорит «сделай md5», уточни, **зачем**. Это два совершенно разных
случая, и путать их опасно:

| Зачем | Правильный инструмент |
|---|---|
| Сгенерировать **случайный ключ или пароль** | `openssl rand` — md5 здесь вообще не при чём |
| Захешировать **пароль пользователя** для базы | bcrypt или argon2. ⚠️ **Никогда не md5** |
| Проверить, что **файл не изменился** при скачивании | вот здесь md5 или sha256 уместны |

**Почему md5 нельзя для паролей.** Он специально сделан быстрым. Обычная видеокарта
перебирает миллиарды вариантов md5 в секунду, поэтому пароль из такой базы
восстанавливают за минуты. Для паролей нужен алгоритм, который **намеренно медленный**
и добавляет к каждому паролю случайную «соль» — bcrypt, argon2, scrypt. Подробнее —
`guard-auth/references/passwords-and-sessions.md`.

Если человек уже хранит пароли в md5 — это находка красного уровня. Меняется не
«добавлением соли», а переходом на bcrypt/argon2 с перехешированием при следующем
входе каждого пользователя.

### Случайный ключ для приложения

Это то, что нужно в 90% случаев: `JWT_SECRET`, `SECRET_KEY`, пароль к базе, токен
для вебхука.

**Linux / macOS / Git Bash:**

```bash
openssl rand -hex 32
```

Вывод — 64 символа, например:

```
7f3a9c2e5b1d8f04a6e2c9b7d3f1a8e5c4b2d9f6a3e7c1b5d8f2a4e6c9b3d7f1
```

**PowerShell (без openssl):**

```powershell
-join ((1..32) | ForEach-Object { '{0:x2}' -f (Get-Random -Maximum 256) })
```

**Варианты длины и формата:**

| Команда | Что даёт | Для чего |
|---|---|---|
| `openssl rand -hex 32` | 64 символа, только цифры и a–f | Универсально: ключи, токены |
| `openssl rand -base64 32` | 44 символа, буквы/цифры/`+/=` | Когда нужно покороче |
| `openssl rand -base64 24` | 32 символа | Пароль к базе данных |
| `openssl rand -hex 16` | 32 символа | Токен в адресе вебхука |

⚠️ В `base64` встречаются символы `+`, `/` и `=`. В некоторых конфигах и в строках
подключения они требуют экранирования и ломают запуск. Если не уверены — берите
`-hex`, там только цифры и буквы.

### Пароль для человека

Пароль, который сотрудник будет вводить руками, должен читаться. Случайная
шестнадцатеричная строка на 64 символа для этого не годится.

```bash
openssl rand -base64 12
```

Даст примерно `K9mQ2vXp4Lz7` — 16 символов, набирается вручную.

Скажи человеку прямо: **лучший пароль — длинная фраза**. `кот-забыл-зонт-в-трамвае`
надёжнее, чем `Qw3!rT`, и запоминается без бумажки. Длина важнее набора символов.

## Шаг 4. Куда положить сгенерированное

Ключ бесполезно сгенерировать и оставить в окне терминала. Три правила:

1. **Сразу сохранить в менеджер паролей.** Не в заметки, не в переписку, не в файл
   на рабочем столе.
2. **В проект — только в файл, который не попадает в git.** Обычно это `.env`,
   и он обязан быть в `.gitignore`.
3. **Поставить права на файл** (Linux/macOS):

```bash
chmod 600 .env
ls -l .env
```

Ожидаемый вывод начинается с `-rw-------` — читает только владелец.

⚠️ Отдельно проверить, что `.env` **не лежит внутри папки сайта**. Если он в корне,
который раздаёт веб-сервер, файл отдаётся по прямой ссылке как обычный текст — все
ключи открыты любому.

## Шаг 5. Проверить контрольную сумму файла

Единственный случай, где md5 и sha256 уместны: убедиться, что скачанный файл не
подменён.

**Linux / macOS / Git Bash:**

```bash
sha256sum файл.zip      # Linux, Git Bash
shasum -a 256 файл.zip  # macOS
md5sum файл.zip         # если автор опубликовал именно md5
```

**PowerShell:**

```powershell
Get-FileHash файл.zip -Algorithm SHA256
Get-FileHash файл.zip -Algorithm MD5
```

Полученную строку сравнить с той, что опубликовал автор файла. Совпала — файл целый.
Не совпала — не запускать.

## Шаг 6. Если что-то пошло не так

Типовые ответы терминала и что они значат:

| Сообщение | Что произошло | Что делать |
|---|---|---|
| `command not found` | Инструмента нет в системе | Установить или использовать вариант для другой оболочки |
| `Permission denied` | Не хватает прав | Добавить `sudo` в начало — ⚠️ только если понимаете, что делает команда |
| `No such file or directory` | Не та папка или опечатка в имени | `pwd` — где вы сейчас; `ls` — что здесь лежит |
| Ничего не вывелось, появилась новая строка | Команда отработала молча | Это нормально, так и задумано |
| Курсор мигает, ничего не происходит | Команда ещё работает или ждёт ввода | Подождать. Прервать — `Ctrl + C` |

## Чего никогда не делать

- ⚠️ **Не вставлять команду, если не понимаете, что она делает.** Попроси объяснить
  словами. Особенно это касается команд с `rm`, `sudo`, `chmod 777`, `curl ... | sh`.
- ⚠️ **Не присылать сгенерированный ключ в чат, в почту или в мессенджер.** Всё,
  что отправлено, считается известным посторонним. Ключ передаётся через менеджер
  паролей.
- ⚠️ **Не использовать «примерный» ключ из инструкции или из интернета.** Ключ из
  статьи знают все, кто эту статью читал. Генерировать всегда свой.
- ⚠️ **Не оставлять ключ по умолчанию.** `changeme`, `secret`, `admin` — первое,
  что перебирают автоматические сканеры.

## Как это звучит в диалоге

> **Плохо:** «Сгенерируйте JWT_SECRET через `openssl rand -hex 32` и добавьте в .env».
>
> **Хорошо:** «Нужен один секретный ключ — это просто длинная случайная строка,
> которой сервер подписывает входы сотрудников. Сделаем за минуту.
>
> Откройте терминал: `Win + X` → «Терминал». Готово? Скажите, и дам команду.»

И дальше — по одному шагу, с проверкой после каждого.
