# Блокировка ботов: nginx, Caddy, Cloudflare

Guard Security Suite © ExcellentMaps — github.com/ExcellentMaps

---

Блокировка отклоняет запрос по строке представления клиента (User-Agent) — тексту, который клиент
сам о себе пишет. Готовый конфиг — `templates/nginx-ai-block.conf`. Сразу о границах: это фильтр
от вежливых, а не защита от целенаправленных, честный разбор ограничений — в конце файла.

---

## Как работает директива map

`map` в nginx — таблица соответствия: «посмотри в переменную, сравни со списком, запиши результат
в другую переменную». Условий может быть сотня, проверка всё равно быстрая.

```nginx
map $http_user_agent $guard_blocked_ua {
    default 0;                      # ничего не совпало — 0
    "~*(GPTBot|ClaudeBot)" 1;       # совпало — 1
}
```

`~*` означает «регулярное выражение, регистр не важен»: `gptbot` и `GPTBot` совпадут одинаково, а
вертикальная черта внутри скобок — это «или».

⚠️ **`map` работает только на уровне `http`**, а не внутри `server { }`: если положить её внутрь,
nginx не запустится вовсе и выдаст `"map" directive is not allowed here`. Поэтому файл кладётся в
`/etc/nginx/conf.d/ai-block.conf` — содержимое этой папки подключается как раз на уровне `http`.
Внутри `server` остаётся только применение — `if ($guard_deny_bot) { return 403; }`.

Шаблон считает решение в три шага и блокирует только при сочетании «UA в списке + путь не исключён
+ IP не исключён».

## Что в шаблоне: разбор по группам

| Группа | Кто это | Блокировать? |
|---|---|---|
| 1. ИИ-краулеры | GPTBot, ClaudeBot, PerplexityBot, Google-Extended, CCBot, Bytespider | почти всегда да |
| 2. Поисковики | Googlebot, Bingbot, YandexBot, DuckDuckBot | **только** если сайт не должен быть в поиске |
| 3. Сканеры уязвимостей | nmap, nikto, sqlmap, nuclei, gobuster, ffuf | всегда да |
| 4. SEO-краулеры | AhrefsBot, SemrushBot, MJ12bot, DotBot, PetalBot | обычно да |
| 5. Простые HTTP-клиенты | curl, wget, python-requests, scrapy, go-http-client | осторожно, см. ниже |
| 6. Пустой User-Agent | клиент не представился вовсе | да |

**Группа 1 — ИИ-краулеры.** Собирают содержимое для обучения моделей и ответов ИИ-поисковиков. Для
публичного сайта решает владелец: запрет убирает не только обучение, но и цитирование со ссылкой.

**Группа 2 — поисковики.** Единственная группа, которую по ошибке блокируют катастрофически. Для
сайта, живущего с поиска, это выстрел себе в ногу: трафик уходит не сразу, и связь с правкой
конфига потом не находят.

**Группа 3 — сканеры уязвимостей.** Блокируются всегда: ни один из них не является вашим
инструментом, если вы его не запускали. Новый сервер они находят в течение часа после появления.

**Группа 4 — SEO-краулеры.** Строят базы ссылок для чужих сервисов: пользы нет, нагрузка есть.

**Группа 5 — простые HTTP-клиенты.** 🟠 Самая опасная группа для включения. Под неё попадает всё
серверное: мониторинг аптайма, скрипты бэкапа, проверки из CI, интеграции на библиотеке
`requests`. Перед включением выпишите всё, что ходит на сайт не из браузера.

**Группа 6 — пустой User-Agent.** Живой браузер всегда представляется, пустая строка — автоматика.

## ⚠️ ТРИ ОБЯЗАТЕЛЬНЫЕ ПРОВЕРКИ ПЕРЕД ВКЛЮЧЕНИЕМ

Это не рекомендации. Каждая из трёх ломала живые системы, и каждая ломает их **тихо** — без ошибки
на экране, без письма, без падения сайта.

### 🔴 Проверка 1. Свои вебхуки внесены в исключения

Вебхук — запрос, который чужой сервис присылает вам сам: подтверждение оплаты, сообщение из
мессенджера, звонок из телефонии. Приходит он машинным клиентом, часто с пустым User-Agent.

Без исключения сервис пришлёт запрос, получит 403, и **больше ничего не случится**: никакой ошибки
у вас. Клиент оплатил — заказ не появился. Связь с правкой конфига находят через недели, когда
кто-то жалуется, что «вы мне не ответили».

```nginx
map $uri $guard_allow_uri {
    default 0;
    "~^/api/webhook/"        1;   # ← ваши пути
    "~^/payment/callback/"   1;
}
```

Где искать свои вебхуки: настройки интеграций в системе, панели платёжного сервиса и мессенджера,
логи сервера за месяц с фильтром по `POST`.

### 🔴 Проверка 2. Путь /.well-known/acme-challenge/ исключён

По этому адресу центр сертификации Let's Encrypt подтверждает, что домен ваш, — и делает это при
каждом продлении, примерно раз в 90 дней. Ходит он туда не браузером.

Без исключения сегодня не произойдёт ничего. Через месяц — тоже. А через три месяца сертификат не
продлится, и **каждый посетитель встретит красную страницу с предупреждением об опасности**.
Чинится это за минуты, но обычно утром выходного дня.

```nginx
"~^/\.well-known/acme-challenge/"  1;   # не трогать
"~^/\.well-known/"                 1;   # заодно и файлы политики
```

Вторая строка нужна и потому, что `security.txt`, `ai.txt` и `tdmrep.json` существуют для машин.

### 🔴 Проверка 3. Поисковики не заблокированы, если сайт должен быть в поиске

Группа 2 в шаблоне включена, потому что шаблон рассчитан на закрытую систему. Для публичного сайта
её нужно **закомментировать до включения**, а не после.

```nginx
    # "~*(Googlebot|Google-InspectionTool|Bingbot|BingPreview|Applebot)"  1;
    # "~*(YandexBot|Yandex|DuckDuckBot|Baiduspider|Sogou|Slurp)"          1;
```

Ошибка проявляется медленно: позиции падают за неделю-две.

## Как проверить, что живой браузер не пострадал

```bash
nginx -t && systemctl reload nginx
D=https://ВАШ_ДОМЕН

# ожидается 200 — обычный посетитель
curl -s -o /dev/null -w "браузер: %{http_code}\n" \
  -A "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 Chrome/120.0" $D/
curl -s -o /dev/null -w "GPTBot:  %{http_code}\n" -A "GPTBot" $D/          # 403
curl -s -o /dev/null -w "sqlmap:  %{http_code}\n" -A "sqlmap/1.7" $D/      # 403
curl -s -o /dev/null -w "acme:    %{http_code}\n" -A "" $D/.well-known/acme-challenge/test  # 200
curl -s -o /dev/null -w "вебхук:  %{http_code}\n" -A "python-requests/2.31" \
  -X POST $D/api/webhook/test                       # 200 или 405, но НЕ 403
```

🔴 Если в строке «браузер» не 200 — немедленно откатывайте: вы блокируете людей.
🟠 Если в строке «вебхук» 403 — исключение не сработало, интеграции сейчас умирают.
🟡 Если в строке «acme» 403 — сертификат не продлится через 90 дней.

После включения загляните в логи ближайших суток — кому вы отдали 403:

```bash
grep ' 403 ' /var/log/nginx/access.log | awk -F'"' '{print $6}' | sort | uniq -c | sort -rn | head -30
```

## Caddy

```caddyfile
example.com {
    @ai_bots {
        header_regexp User-Agent "(?i)(GPTBot|ClaudeBot|Claude-User|PerplexityBot|CCBot|Bytespider|anthropic-ai|Google-Extended|Amazonbot|Diffbot)"
        not path /.well-known/*
        not path /api/webhook/*
    }
    respond @ai_bots 403

    @scanners header_regexp User-Agent "(?i)(nmap|nikto|sqlmap|masscan|nuclei|wpscan|gobuster|ffuf)"
    respond @scanners 403
    reverse_proxy localhost:3000
}
```

`(?i)` — то же, что `~*` в nginx: игнорировать регистр. Строки `not path` — те самые обязательные
исключения.

## Cloudflare

Если сайт за Cloudflare, блокировать лучше там: запрос отсеивается **до** вашего сервера, и трафик
до него вообще не доходит.

| Инструмент | Что делает |
|---|---|
| Блокировка ИИ-краулеров | одним переключателем закрывает известные ИИ-краулеры; список поддерживает Cloudflare |
| Защита от ботов | отсеивает автоматику по поведению, а не по строке представления |
| Правила WAF | собственные условия: по UA, стране, пути, частоте |
| Ограничение частоты | предел запросов с адреса за интервал |

Правило WAF пишется выражением — логика та же, с исключением пути:

```text
(http.user_agent contains "GPTBot" or http.user_agent contains "ClaudeBot")
and not starts_with(http.request.uri.path, "/.well-known/")
```

Главное преимущество: список известных ИИ-ботов поддерживает Cloudflare, а не вы — новые краулеры
появляются постоянно.

⚠️ Названия разделов в панели Cloudflare меняются — перед тем как диктовать человеку шаги,
сверьтесь с актуальной документацией. Правило и источники — `owner-actions.md`.

## Честно об ограничениях

Строка User-Agent — это текст, который клиент пишет о себе сам, никакой проверки за ней не стоит.
Обход выглядит так: `curl -A "Mozilla/5.0 (Windows NT 10.0; Win64; x64)"`. Любая библиотека для
скрапинга умеет это из коробки, обычно параметром по умолчанию.

| Блокировка по User-Agent | Результат |
|---|---|
| Останавливает крупные ИИ-краулеры | да, они представляются честно |
| Останавливает сканеры «по площадям» | да, массовые сканы шумят стандартными строками |
| Снимает мусорную нагрузку и чистит логи | да, и это само по себе ценно |
| Останавливает того, кто целенаправленно выкачивает **ваш** сайт | 🔴 нет |

Против целенаправленной выкачки работает другое: **авторизация** (`guard-auth`), **ограничение
частоты** (`guard-server`), **поведенческая защита** Cloudflare и **ловушки**
(`honeypots-and-limits.md`).

Отдельно скажите владельцу вслух: блокировка не защищает от копирования внешнего вида сайта — всё,
что показано в браузере, уже находится на компьютере посетителя. См. `guard-frontend`, `myths.md`.
