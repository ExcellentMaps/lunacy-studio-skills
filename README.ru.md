## Что это

Guard Security Suite — набор [скиллов](https://docs.claude.com/en/docs/agents-and-tools/agent-skills)
для Claude Code. Устанавливается один раз. Дальше вы пишете обычными словами —
*«проверь мой проект»*, *«что у меня не защищено»*, *«защити CRM»* — и Claude
проводит структурный аудит, объясняет каждую находку языком, понятным человеку
без технического образования, и закрывает их по одной: с проверкой и с записанным
откатом на каждый шаг.

Сделан прежде всего под **CRM-системы и рабочие приложения** — там, где лежат карточки
клиентов, заказы, телефоны и учётные записи сотрудников. При этом скиллы не привязаны
к стеку и работают на любом веб-проекте: PHP, Node, Python, Go, Ruby, .NET;
PostgreSQL, MySQL, MongoDB; nginx, Caddy, Apache, Cloudflare; VPS, Docker, облако
или обычный хостинг.

### Три вещи, которые он делает

| | |
|---|---|
| **1. Находит** | Двенадцать блоков проверок: код, история git, права в базе, живой сайт снаружи, зависимости и то, что специфично именно для CRM. Аудит только читает — он ничего не меняет. |
| **2. Объясняет** | Каждая находка — четыре строки: что открыто, что из-за этого может случиться, чем закрывается, сколько времени займёт. Ни одного термина без бытового объяснения. |
| **3. Закрывает** | По одному слою за раз, у каждого своя проверка и свой откат. Ничего не применяется без показа плана заранее. |

## Правило номер один: не сломать работающее

Защита, которая положила рабочий сайт, хуже отсутствия защиты — владелец откатит
всё и больше не подпустит. Поэтому каждое изменение идёт по одному циклу:

```
ПОСМОТРЕТЬ  →  СОХРАНИТЬ  →  ИЗМЕНИТЬ ОДНО  →  ПРОВЕРИТЬ  →  ЗАПИСАТЬ ОТКАТ
```

Всё, что может закрыть владельцу доступ к собственной системе — firewall, защита SSH,
строгий CSP, двухфакторка, — делается **в последнюю очередь** и всегда со второй
открытой сессией на сервер: она спасательный круг, если правило отрежет доступ.

## Установка

### Рекомендуемый способ — как плагин

```
/plugin marketplace add ExcellentMaps/lunacy-studio-skills
/plugin install excellentmaps@lunacy-studio-skills
```

Всё. Все семь скиллов подключаются разом и потом обновляются одной командой:

```
/plugin marketplace update lunacy-studio-skills
```

### Другой способ — скопировать скиллы руками

Скиллы лежат в `~/.claude/skills/` (работают во всех проектах) или в `.claude/skills/`
внутри проекта (только в нём).

**Windows (PowerShell)**

```powershell
git clone https://github.com/ExcellentMaps/lunacy-studio-skills.git
New-Item -ItemType Directory -Force $HOME\.claude\skills | Out-Null
Copy-Item -Recurse lunacy-studio-skills\plugins\excellentmaps\skills\* $HOME\.claude\skills\
```

**macOS / Linux**

```bash
git clone https://github.com/ExcellentMaps/lunacy-studio-skills.git
mkdir -p ~/.claude/skills
cp -r lunacy-studio-skills/plugins/excellentmaps/skills/* ~/.claude/skills/
```

### Проверка

Перезапустите Claude Code и проверьте:

```
/skills
```

В списке должно появиться семь пунктов: `security-guard` и шесть `guard-*`.

## Как пользоваться

Название скилла запоминать не нужно. Вы описываете задачу — Claude сам выбирает нужный.

```
Проверь мой проект на дыры в безопасности
Защити мою CRM — с чего начать?
Что у меня сейчас не защищено?
Настрой защиту от ИИ-ботов и скраперов
Проверь, что вход защищён от подбора пароля
Кажется, кто-то залез в систему — что делать?
```

### Сквозной сценарий

Скажите «защити мой проект» — и набор проведёт всю работу одним потоком: сам делает,
сам проверяет результат и на каждом шаге говорит, что дальше.

| Этап | Что происходит |
|---|---|
| 0 | Четыре вопроса, по одному за раз, каждый с объяснением зачем |
| 1 | Аудит — только чтение, ничего не меняется |
| 2 | План: что меняем, чем проверим, как откатим, насколько рискованно |
| 3 | Внедрение по одному пункту, после каждого — отчёт из четырёх строк |
| 4 | Чеклист того, что вы включаете сами в панелях своих сервисов |
| 5 | Перепроверка: дыра закрыта, только когда проверка перестала срабатывать |
| 6 | **Итоговый отчёт: что было → что стало → что теперь защищено и от чего** |

Всё, что может закрыть вам доступ к собственной системе — firewall, SSH, строгий CSP,
двухфакторка, — идёт последним и никогда не применяется без вашего участия.

**Язык.** По умолчанию набор работает на английском и один раз спрашивает, не удобнее
ли продолжить по-русски. Ответьте на любом языке в любой момент — он переключится.

На каждом шаге Claude заканчивает строкой «**Дальше:** …» — одним конкретным действием.
Без «вот вам десять вариантов, разбирайтесь».

## Семь скиллов

| Скилл | Слой | Что закрывает |
|---|---|---|
| **`security-guard`** | Вход в набор | Модель семи слоёв, план внедрения, отчёт владельцу, словарь терминов |
| **`guard-audit`** | Найти | 12 блоков проверок, три скрипта, приоритеты, действия при взломе |
| **`guard-auth`** | Вход и права | Хеширование паролей, защита от перебора, сессии, 2FA, роли, доступ к чужим записям |
| **`guard-data`** | База | Права, RLS, `SECURITY DEFINER`, SQL-инъекции, персональные данные, журнал, бэкапы |
| **`guard-server`** | Периметр | Порты, firewall, TLS, заголовки, CSP, лимиты запросов, SSH, секреты |
| **`guard-frontend`** | Браузер | XSS, куки, localStorage, CSRF, зависимости, ключи в сборке |
| **`guard-ai-policy`** | Боты и ИИ | `llms.txt`, `ai.txt`, `robots.txt`, `security.txt`, блокировка ботов, ловушки |

## Аудит — главная функция

`guard-audit` — сердце набора. В нём три скрипта, и все три только читают:

```bash
bash scripts/audit-code.sh /путь/к/проекту   # секреты, история git, опасный код, зависимости
bash scripts/audit-live.sh ваш-домен.ru      # заголовки, TLS, открытые файлы, реакция на ботов
psql "$DATABASE_URL" -f scripts/audit-db.sql # права, RLS, SECURITY DEFINER, политики
```

Находки сортируются по двум осям и только по ним: **что теряем** × **насколько легко это
сделать снаружи**. Поэтому отчёт начинается с того единственного, что действительно важно,
а не со стены красного цвета, в которой тонет главное.

Скрипты покрывают механическое. Логика прав и доступ к чужим записям проверяются чтением
кода — этим занимается сам скилл.

## Про защиту от ИИ — честно

`guard-ai-policy` раскладывает по сайту `llms.txt`, `/.well-known/ai.txt`, `robots.txt`,
`security.txt` и `tdmrep.json`, ставит заголовок `X-Robots-Tag` и мета-теги `noai`,
настраивает блокировку ботов для nginx, Caddy и Cloudflare.

**Что эти файлы делают.** Они объявляют ваши правила. Крупные ИИ-краулеры — GPTBot,
ClaudeBot, PerplexityBot, Google-Extended и остальные — заявленный запрет соблюдают
и уходят. Явно опубликованное заявление, что сервис частный и доступ только по лицензии,
лишает нарушителя аргумента «данные были открыты». И это же заявление видит ИИ-ассистент,
когда ему скидывают ваш сайт и просят скопировать систему или обойти вход.

**Чего они не делают.** Текстовый файл не может заставить программу подчиниться.
Самописный скрипт проигнорирует всё сразу. Поэтому файлы политики ставятся **вместе**
с ограничением частоты запросов, блокировкой ботов и — главное — авторизацией,
а не вместо них.

Скилл говорит это владельцу прямым текстом. Ложное чувство защищённости хуже,
чем честное понимание границ.

## Что нужно

- Claude Code (любая свежая версия)
- `curl` и `grep` — для скриптов аудита
- По желанию, используются если установлены: `git`, `openssl`, `npm`,
  [`gitleaks`](https://github.com/gitleaks/gitleaks),
  [`osv-scanner`](https://github.com/google/osv-scanner),
  [`semgrep`](https://github.com/semgrep/semgrep),
  [`trivy`](https://github.com/aquasecurity/trivy),
  [`lynis`](https://github.com/CISOfy/lynis)

Скрипты написаны на обычном shell и работают на Linux, macOS, в WSL и в Git Bash
на Windows.

## Границы

**Работает с:** проектами, которые принадлежат вам или на работу с которыми у вас
есть разрешение.

**Отказывает всегда:** аудит и атака чужих систем, обход авторизации, обход чужих
лимитов и капч, извлечение данных из сервисов, которые вам не принадлежат. Это записано
в инструкциях самих скиллов — они отказываются от таких просьб.

**Не заменяет:** живого пентестера, юридическое оформление обработки персональных
данных (GDPR, 152-ФЗ) и постоянную работу с безопасностью. Задача набора — поднять цену
взлома выше ценности данных и сделать попытки заметными. Невзламываемых систем не бывает.
